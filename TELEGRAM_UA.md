# Telegram для Emplivo

Підготовлено інтеграцію **публічна група вакансій + приватний бот анкет**.
Адресу-запрошення групи та username `Emplivobot` внесено в публічну конфігурацію.
Посилання на групу ввімкнене. Приймання анкет ботом вимкнене (`botEnabled: false`)
до налаштування приватного сервера; реєстрація webhook не виконувалась.
Бот не публікує анкети в групі й не розміщує вакансії автоматично.

## 1. Що зробити у Telegram

1. Відкрийте офіційного **@BotFather**, надішліть `/newbot`.
   Назва: `Emplivo — анкети кандидатів`. Придумайте вільний username, який
   закінчується на `bot`. Збережіть отриманий токен лише у приватних
   налаштуваннях PHP-хостингу. Не надсилайте його в чат, GitHub або браузерний JS.
2. У Telegram: **Нова група → назва «Emplivo | SPA · Wellness · Fitness»**.
   Відкрийте налаштування групи → **Тип групи → Публічна** та виберіть вільну
   адресу `https://t.me/…`. За потреби налаштуйте право публікації лише
   адміністраторам. Не додавайте сторонніх людей без їхньої згоди.
3. Можна додати бота до групи як учасника. Для приватних анкет він не потребує
   адміністративних прав і може працювати без членства у групі. Залиште Privacy
   Mode у BotFather ввімкненим. Групові повідомлення webhook ігнорує.
4. Власник/менеджер має відкрити приватний чат із ботом. Бот не може написати
   менеджеру першим. Після налаштування закріпіть у групі посилання на бота
   з `?start=apply`; поясніть, що анкети надсилають приватно.

Кнопка групи також підтримує посилання-запрошення `https://t.me/+…`.
Таке посилання саме по собі не означає, що група має публічний username.
Для публічної групи виберіть вільну адресу `https://t.me/назва` в налаштуваннях.
Токен бота потрібний лише приватному серверу. Номер чату з `web.telegram.org`
не замінює посилання для вступу та не є ID особистого чату менеджера.

## 2. Де працюватиме бот

GitHub Pages https://vadisimus.github.io/Emplivo/ показує сайт і може містити
посилання на Telegram. Для відповідей бота потрібний доступний з інтернету
HTTPS endpoint на PHP-хостингу:

`https://www.emplivo.com.ua/api/telegram-webhook.php`

Потрібні PHP 8.3+, cURL, Sodium, запис у приватний каталог і вихідний HTTPS
до `api.telegram.org:443`. Вхідні POST від Telegram не повинні блокуватися
паролем, Cloudflare challenge чи правилами WAF. HTTP 403 при неправильному
секреті очікуваний; GET повертає 405. Сам GitHub Pages PHP не виконує.

## 3. Приватні налаштування на хостингу

Малий пакет серверних файлів: [downloads/emplivo-telegram-setup.zip](downloads/emplivo-telegram-setup.zip).
Завантажте його в `www` вашого домену й розпакуйте саме там: після розпакування
має бути `www/api/telegram-webhook.php`. Архів не містить приватного `telegram.php`
і не замінює вже збережений токен. Видаліть завантажений ZIP із хостингу після
розпакування. Його можна повторно зібрати командою `python tools/package_telegram.py`.

Завантажте нові `api/`, `tools/telegram_admin.php`, `tools/TelegramPrivateConfig.php`,
`tools/telegram_init.sh`,
публічний `telegram-config.js` і шаблон із `config/`.
У файловому менеджері хостингу створіть **поза публічною папкою `www`**:

```text
каталог-домену/
├── www/                         ← публічні файли сайту
├── emplivo-private/
│   ├── config.php               ← чинні налаштування сайту; зберегти
│   └── telegram.php             ← заповнена копія config/telegram.example.php
└── telegram-state/              ← зашифровані тимчасові записи
```

Права: `emplivo-private` і `telegram-state` — 700, `telegram.php` — 600.
PHP має працювати від власника цих каталогів.

**Рекомендований спосіб збереження токена:** з папки `www` запустіть
`bash tools/telegram_init.sh`. Вставте новий токен лише після появи запиту
в терміналі й натисніть Enter. Символи не відображаються. Токен не входить
до тексту команди або історії shell; приватний PHP-файл створюється автоматично.
Скрипт може замінити неправильно оформлений файл. У правильному файлі він
зберігає наявні ключі шифрування та ID менеджера при зміні токена.

Для ручного налаштування `telegram.php` має бути **повним PHP-файлом**:

```php
<?php
return [
    'bot_token' => 'ВСТАВТЕ_НОВИЙ_ТОКЕН_ЛИШЕ_НА_СЕРВЕРІ',
    'bot_username' => 'Emplivobot',
];
```

Окремі рядки `'bot_token' => ...` без `<?php` та `return [...]` не є PHP-конфігурацією.
Завантажувач відхиляє неправильний файл без показу його вмісту. Якщо токен
вже відобразився в чаті чи журналі, перевипустіть його через @BotFather `/revoke`
і збережіть новий через прихований запит. Не вставляйте токен у повідомлення.

Повний перелік налаштувань:

| Поле | Значення |
|---|---|
| `bot_token` | Токен @BotFather, тільки на сервері |
| `bot_username` | Реальний username бота без `@` |
| `webhook_secret` | Випадковий секрет: `bin2hex(random_bytes(32))` |
| `state_key` | Ключ: `base64_encode(random_bytes(32))` |
| `admin_chat_id` | Позитивний ID особистого чату менеджера, отриманий нижче |
| `group_url` | Адреса групи `https://t.me/…` або запрошення `https://t.me/+…` |
| `site_url` | `https://www.emplivo.com.ua`, без кінцевого `/` |
| `state_dir` | Абсолютний шлях до приватного `telegram-state` поза `www` |

Генеруйте два секрети на сервері засобами PHP. Не вводьте токен у команди
curl або аргументи команд, де він потрапить в історію. Шаблон не містить секретів.

Якщо ви вже зберегли лише токен, команда `prepare` нижче створить відсутні
`webhook_secret` та `state_key`, додасть публічні адреси з `telegram-config.js`
і шлях до приватного каталогу стану. Вона не показує та не змінює токен,
не перезаписує заповнені поля й не реєструє webhook. Повторний запуск
зберігає наявні ключі. Заповнений файл зберігається з правами 600.

## 4. Запуск у терміналі PHP-хостингу

Перейдіть у фактичну публічну папку `www`. Шляхи в командах відносні до неї.

```bash
php -v
php --ri curl
php --ri sodium
bash tools/telegram_init.sh
php tools/telegram_admin.php admin-id
```

Остання команда працює **до реєстрації webhook**: покаже одноразову команду
`/id …`. Надішліть її боту зі свого особистого Telegram, поверніться в
термінал і натисніть Enter. Команда збереже позитивний ID у `admin_chat_id`
автоматично, не виводячи токен.
Якщо повідомлення не знайдено, повторіть перед публічним оголошенням бота.
Від’ємний ID групи конфігурація відхиляє.

```bash
php tools/telegram_admin.php check
php tools/telegram_admin.php register
php tools/telegram_admin.php status
```

`register` звіряє @username через `getMe`, встановлює webhook із секретом,
`max_connections=1` та меню команд. Токен не виводиться. Наявний webhook
буде змінений; використовуйте окремого бота Emplivo, а не чужого робочого бота.

У планувальнику хостингу додайте **щогодинне** виконання:

```text
php /АБСОЛЮТНИЙ/ШЛЯХ/www/tools/telegram_admin.php cleanup
```

Використайте шлях до PHP 8.3+, якщо типовий `php` має іншу версію. Очищення
видаляє зашифровані записи через 24 години неактивності; фактичне видалення
може запізнитися до одного інтервалу планувальника. Незавершені анкети після
1 години неактивності бот не продовжує. Порожній файл блокування не містить анкет.
Не включайте `telegram-state` у довгострокові резервні копії; приватну конфігурацію
зберігайте лише в захищеній резервній копії з доступом відповідального адміністратора.

## 5. Перевірка та кнопки сайту

У власному приватному чаті пройдіть `/apply`: згода → ім’я → телефон/email →
посада → місто → досвід → перевірка → «Надіслати заявку».
До останнього кроку менеджер не отримує анкету. Перевірте отримання в його
особистому чаті, `/cancel` та `/jobs`. Публічна група не повинна містити контакти.
Видаліть свою тестову анкету з обох чатів після перевірки.

Лише після успішного тесту підключіть публічні адреси з кореня репозиторію:

```bash
python tools/configure_telegram.py --group-url 'https://t.me/REAL_GROUP_USERNAME' --bot-username 'Emplivobot' --enable-bot
```

Замініть адресу групи реальною адресою (підтримується й `https://t.me/+…`).
Без `--enable-bot` публікується лише кнопка групи, а анкета бота вимкнена.
Параметр `--enable-bot` використовуйте після перевірки реальної доставки менеджеру.
Інструмент змінює лише публічні
посилання в `telegram-config.js` і HTML; токен не приймає. Додаються кнопки
у футері UK/EN та біля загальної анкети на головній. Працюють і шляхи `/Emplivo/`.
Після перегенерації HTML повторіть цю команду; вона ідемпотентна.
Завантажте змінені файли сайту на PHP-хостинг або опублікуйте зміни в гілці,
яку використовує GitHub Pages. Звичайне додавання токена до GitHub Secrets
не створює цілодобовий PHP-сервер і не запускає webhook.

## Межі першої версії та обслуговування

- Анкета бота українською. Бот не завантажує файли CV; для них використовуйте
  чинну форму PHP-сайту або email. До ATS/бази сайту ці анкети автоматично не записуються.
- Вакансії в групі публікує адміністратор вручну. Вигадані приклади із сайту
  не публікуйте як справжні вакансії. Автоматична публікація потребує джерела
  підтверджених вакансій і окремої інтеграції.
- Telegram і менеджер також зберігають повідомлення. Регламент цієї конфігурації:
  менеджер вручну видаляє отримані анкети не пізніше 90 днів і опрацьовує запити
  на видалення через hr@emplivo.com.ua. До ввімкнення підтвердьте цей процес;
  `cleanup` очищає лише серверні записи, не повідомлення Telegram.
- Повтори webhook не повторюють уже підтверджене надсилання. Після неоднозначного
  мережевого таймауту Telegram може прийняти повідомлення без відповіді; тоді
  повтор може створити дубль. Звіряйте стабільний номер `#…` заявки.
- Перевіряйте `status`, чергу оновлень, HTTPS та виконання очищення. Логи не
  повинні містити тіло запиту, токен, контакти чи повні URL Bot API.
- Для зупинки: `php tools/telegram_admin.php disable`, приберіть кнопку бота
  з публічної конфігурації повторним запуском configure_telegram.py без `--enable-bot`.
  У разі розкриття токена перевидайте його в BotFather,
  оновіть приватну конфігурацію і повторіть `register`. Ключ стану збережіть,
  або видаліть старі `.bin` перед його заміною.

## Локальні перевірки розробника

```bash
php tools/test_telegram.php
php tools/test_telegram_setup.php
python tools/test_telegram_secret_io.py
python tools/test_telegram_webhook.py
python tools/test_telegram_config.py
node tools/verify_telegram.cjs
node tools/verify_github_pages.cjs
```

HTTP-тест використовує `php` із PATH або `EMPLIVO_PHP`. Браузерним тестам
потрібні Playwright і Chromium. Усі Telegram-запити в тестах замінені локальними
імітаціями: реальних повідомлень і записів у робочій базі вони не створюють.
